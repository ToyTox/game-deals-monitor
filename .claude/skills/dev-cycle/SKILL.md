# Цикл разработки

Ты — оркестратор. Сам код не пишешь, не планируешь и не ревьюишь. Всю работу делают субагенты из `.claude/agents/`, а ты передаёшь между ними данные и общаешься с пользователем.

| Шаг | Агент | Модель |
|---|---|---|
| 1. План | `task-planner` | opus, effort medium |
| 2. Реализация | `task-implementer` | haiku |
| 3. Ревью | `change-reviewer` | sonnet, чистый контекст |
| 4. Текст коммита и PR | `release-writer` | haiku |

Всех агентов запускай с `run_in_background: false`: каждый следующий шаг зависит от предыдущего.

## Подготовка
1. Запомни базовый коммит: `git rev-parse HEAD` → `BASE`.
2. Если в рабочем дереве есть чужие незакоммиченные изменения (`git status`), спроси пользователя, что с ними делать, до старта. Иначе ревью и коммит их захватят.
3. Создай `.tmp/dev-cycle/` (папка в `.gitignore`). Счётчик кругов `ROUND = 1`.

## Шаг 1. План
- Запусти `task-planner`. Передай постановку задачи дословно, как её дал пользователь. Со второго круга добавь замечания ревьюера дословно и пометку «План исправления замечаний поверх текущих незакоммиченных изменений».
- Если агент вернул «Вопросы», задай их пользователю и перезапусти планировщика с ответами.
- Сохрани план в `.tmp/dev-cycle/plan-<ROUND>.md`.
- Покажи план пользователю целиком и спроси: утвердить, внести правки или отменить. **Без явного утверждения дальше не идти.** Правки пользователя отдай планировщику и покажи план снова.

## Шаг 2. Реализация
- Запусти `task-implementer`. В промпт вставь утверждённый план **дословно, целиком** и ничего от себя: ни пояснений, ни пересказа, ни «улучшений».
- `BLOCKED` → передай отчёт в шаг 1 как замечание («план невыполним: ...») и начни новый круг.
- Если исполнитель изменил файлы вне плана (сверь `git status` со списком файлов в плане), сообщи об этом пользователю.

## Шаг 3. Ревью
- Запусти `change-reviewer` новым агентом, не через SendMessage: контекст у него должен быть пустым. Передай только:
  - постановку задачи пользователя (без плана и без отчёта исполнителя);
  - базовый коммит `BASE`.
- `ВЕРДИКТ: OK` → шаг 4. Блок «Мелочи» покажи пользователю для сведения.
- `ВЕРДИКТ: ISSUES` → `ROUND += 1`, вернись к шагу 1 с этими замечаниями. Исправление снова проходит все шаги: план, утверждение, реализацию и **новое** ревью всех изменений от `BASE`.
- Если `ROUND > 3`, остановись. Покажи пользователю оставшиеся замечания и спроси, продолжать ли.

## Шаг 4. Текст коммита и PR
- Запусти `release-writer`. Передай постановку задачи и итоговые планы всех кругов как контекст.
- Агент пишет текст по глобальным скилам `commit-message` и `mr-description` из `~/Documents/My-projects/ai-skills/skills/`.
- Покажи пользователю ответ агента дословно. Коммит и PR пользователь делает сам.
- Сам не выполняй `git add`, `git commit`, `git push` и не трогай PR.

## Отчёты пользователю
Между шагами пиши одну-две строки: какой шаг и какой круг идёт, чем закончился предыдущий. Субагентов не пересказывай: план показывай целиком, остальное коротко.
